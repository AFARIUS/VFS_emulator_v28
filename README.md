# VFS Emulator (Вариант 28)

Эмулятор командной оболочки UNIX-подобной ОС. Этап 1: REPL.

## Описание

Приложение реализует консольный интерфейс (CLI) с приглашением, содержащим имя VFS.
Поддерживаются команды-заглушки `ls`, `cd`, а также команда `exit`.
Неизвестные команды обрабатываются с выводом сообщения об ошибке.

## Функции и настройки

- Имя VFS задается в `Main.java` (по умолчанию `VFS28`).
- Парсер разделяет ввод на команду и аргументы по пробелам.
- Команды `ls` и `cd` выводят свое имя и переданные аргументы.
- Команда `exit` завершает работу.

## Сборка и запуск

### Требования
- Java 17+
- Gradle (используется wrapper)

### Сборка
```bash
./gradlew build
```
### Запуск
```bash
./gradlew run
```

## Этап 2. Configuration

### Описание

Добавлена поддержка параметров командной строки:

- `--vfs <path>` — путь к физическому расположению VFS
  (на этом этапе файл не загружается, параметр сохраняется и выводится).
- `--script <path>` — путь к стартовому скрипту.

При запуске эмулятор выводит отладочную информацию о заданных параметрах.

Если указан `--script`, эмулятор выполняет команды из файла последовательно,
пропуская ошибочные строки. Ввод и вывод отображаются в консоли, имитируя
диалог. После скрипта, если не было команды `exit`, запускается интерактивный
режим.

### Функции и настройки

- `Config` — хранит пути VFS и стартового скрипта.
- `CliParser` — разбирает аргументы `--vfs` и `--script`.
- `ScriptRunner` — читает скрипт, выполняет команды, пропускает ошибки.
- `Shell.executeLine(String)` — выполняет одну строку, возвращает `true` при успехе.
- `Shell.getPrompt()` — возвращает строку приглашения.
- `Shell.isRunning()` — сообщает, активна ли оболочка.

### Команды сборки и запуска

```bash
./gradlew build                # сборка
./gradlew test                 # запуск тестов
./gradlew run                  # интерактивный режим
./gradlew run --args="--vfs ./vfs-data.json --script ./scripts/startup.txt"
```

Скрипты тестирования параметров (папка `scripts/`):

- `ltest-1.sh` / `wtest-1.bat` — базовые сценарии (Linux / Windows).
- `ltest-2.sh` / `wtest-2.bat` — особые случаи (Linux / Windows).

## Этап 3. VFS

### Описание

Добавлена загрузка виртуальной файловой системы из JSON-файла.
Все данные размещаются в памяти; исходный файл только читается
и не модифицируется. Двоичное содержимое файлов кодируется в base64.

При запуске с параметром `--vfs <path>` эмулятор загружает VFS
и выводит строку `VFS loaded: <имя> (<число узлов> nodes)`.
При ошибке загрузки выводится сообщение `Failed to load VFS: ...`.

### Формат JSON

```json
{
  "name": "VFS28",
  "root": {
    "type": "dir",
    "children": {
      "readme.txt": { "type": "file", "content": "SGVsbG8=" },
      "docs": {
        "type": "dir",
        "children": {
          "guide.txt": { "type": "file", "content": "R3VpZGU=" }
        }
      }
    }
  }
}
```

- `type` — `dir` или `file`.
- `children` — объект, отображающий имена потомков на узлы.
- `content` — содержимое файла в base64.

### Образцы VFS

- `vfs/min-vfs.json` — минимальная VFS (только корень).
- `vfs/standart-vfs.json` — VFS с несколькими файлами и папкой.
- `vfs/deep-vfs.json` — VFS с четырьмя уровнями вложенности.
- `vfs/invalid-vfs.json` — неправильно оформленный JSON для тестирования ошибок.

### Скрипты тестирования

- `ltest-3.sh` / `wtest-3.bat` — загрузка трёх вариантов VFS (Linux / Windows).
- `ltest-4.sh` / `wtest-4.bat` — ошибки и совместная работа с `--script` (Linux / Windows).

## Этап 4. Основные команды

### Описание

Реализованы команды, имитирующие работу UNIX-подобной командной строки:

- `ls [path]` — выводит содержимое каталога.
- `cd <path>` — меняет текущий каталог. Поддерживает `..`, `.`, `/` и относительные пути.
- `history` — выводит историю введённых команд.
- `uptime` — выводит время работы эмулятора.
- `tail [-n N] <file>` — выводит последние N строк файла (по умолчанию 10).

Все команды работают с загруженной VFS. Если VFS не загружена, команды `ls`, `cd`, `tail` выводят сообщение об ошибке.

### Функции и настройки

- `Command` — интерфейс команды.
- `CommandContext` — контекст: VFS, корень, текущий каталог, история, время запуска.
- `CommandRegistry` — реестр команд.
- `PathResolver` — определение абсолютных и относительных путей.
- `LsCommand`, `CdCommand`, `HistoryCommand`, `UptimeCommand`, `TailCommand`, `ExitCommand` — реализации.

### Скрипты тестирования

- `ltest-5.sh` / `wtest-5.bat` — базовые команды (Linux / Windows).
- `ltest-6.sh` / `wtest-6.bat` — обработка ошибок (Linux / Windows).

## Этап 5. Дополнительные команды

### Описание

Реализованы команды, изменяющие состояние VFS в памяти,
и служебная команда для вывода справки:

- `rmdir <path>` — удаляет пустой каталог из VFS.
  Не работает для корня, непустых каталогов и файлов.
- `help` — выводит список доступных команд с описанием.

Все модификации выполняются только в памяти; исходный JSON-файл
не изменяется.

### Скрипты тестирования

- `ltest-7.sh` / `wtest-7.bat` — базовые сценарии `rmdir` и `help` (Linux / Windows).
- `ltest-8.sh` / `wtest-8.bat` — граничные случаи (Linux / Windows).
